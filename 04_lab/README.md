## 目录用途

| 目录 | 放什么 | 是否入 Git |
|---|---|---|
| `images/` | 靶机 OVA / ISO / 导出镜像 | ❌ 忽略 |

## 备份与回滚策略（v1.2：VirtualBox 有快照）

> **主用 VirtualBox**：快照免费、随时回滚，标准动作就是 `机器 → 备份 → 生成备份`。
> 下面保留的 VMware Player 方案，以及 `scripts/backup-vm.ps1`，作为无快照环境或整机迁移时的兜底。

| 对象 | 策略 |
|---|---|
| 攻击机（Kali） | VirtualBox 快照 `clean`（装完工具）→ 再拍 `tools-YYYYMMDD` |
| 本地靶机 | 每次开工前拍 `clean`，收工恢复；确认无用后删快照，别囤 |
| 在线靶机（THM/HTB） | 用完即销毁实例，不保留 |
| 需要整机迁移/归档时 | `scripts\backup-vm.ps1`（**必须关机**，开机复制会得到损坏的磁盘） |

**回滚不是洁癖**：靶机被自己改坏、被 exploit 打崩是常态。有快照，你敢乱试；没快照，你会在每个操作前犹豫，效率反而更低。

## 网络（VirtualBox 专用，v1.2）

- **Host-only 负责两机互通，NAT 负责攻击机联网。** 攻击机使用双网卡：
  - 网卡 1：`NAT`，用于 `apt` 和工具下载；
  - 网卡 2：`Host-only`，与靶机共用同一个 VirtualBox Host-only 适配器。
- 本机已验证 `192.168.56.0/24`：Kali 为 `.103`，phpblog 为 `.101`。
- 两台虚拟机不要各用独立的单机 NAT，否则彼此隔离；也不要混用 VMware 与 VirtualBox 的虚拟网络。
- **不要让靶机桥接到物理网络**：等于把一台有漏洞的机器直接接进宿舍/校园网，安全与合规上都说不通。
- 固件仿真（firmadyne / FirmAE）默认会起独立网桥，跑完记得清理，避免和真实网段冲突。
- 实验网段与实验室 `Seed Intelligent Analysis` 的实体设备网段（见其《实验环境网络配置流程》）**物理隔离**，不要混用。
