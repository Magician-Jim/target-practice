# 实验环境与样本

> 只放"重东西"和"要复用的东西"。一次性脚本放对应靶机目录里，不要往这里堆。

## 目录用途

| 目录 | 放什么 | 是否入 Git |
|---|---|---|
| `images/` | 靶机 OVA / ISO / 导出镜像 | ❌ 忽略 |
| `vulhub/` | docker-compose 漏洞环境（一个 CVE 一个子目录） | ✅ 只提交 compose 文件和 README |
| `firmware/` | 固件样本（第 5 周起，优先实验室已有型号） | ❌ 忽略 |
| `tools/` | 自己写的小工具（批量扫描、结果解析、报告生成） | ✅ 提交源码 |

## 快照与回滚策略

| 对象 | 策略 |
|---|---|
| Kali 攻击机 | 装完立即打 `clean` 快照；装完新工具再打一个 `tools-YYYYMMDD` |
| 本地靶机 | 每次开工前打 `clean`，收工回滚 |
| 在线靶机（THM/HTB） | 用完即销毁实例，不保留 |

**回滚不是洁癖**：靶机被自己改坏、被 exploit 打崩是常态。有快照，你敢乱试；没快照，你会在每个操作前犹豫，效率反而更低。

## 网络

- 攻击机与靶机统一走 VMware NAT 网段，**不要让靶机桥接到物理网络**。
- 固件仿真（firmadyne / FirmAE）默认会起独立网桥，跑完记得清理，避免和真实网段冲突。
- 实验网段与实验室 `Seed Intelligent Analysis` 的实体设备网段（见其《实验环境网络配置流程》）**物理隔离**，不要混用。
