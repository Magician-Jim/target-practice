# 打靶机训练工作区（target-practice）

> 负责人：黄子沣　｜　方向：IoT 漏洞挖掘　｜　节奏：每周 1 台，周一交付周报
> 本目录是打靶机训练的**唯一工作区**：过程记录、周报、WP、可复用知识全部沉淀在这里。
> 目标：4 周建立攻击链直觉，8 周从通用靶机过渡到固件分析。

## 这个目录解决什么问题

打靶机最容易烂尾的三种方式：**过程不记录**（打完就忘，周报靠回忆）、**文件到处扔**（找回一次要十分钟）、**知识不沉淀**（打了 20 台，换个场景还是从零开始）。

本目录用三条规则对治：

1. **一台靶机一个文件夹**，编号与"五段式"一一对应，文件落哪里不需要思考；
2. **REPORT.md 是唯一源**，`02_reports/` 只是按实验室命名导出的副本，杜绝两份文档改串；
3. **每次打完必须往 `03_knowledge/` 交一条可复用结论**，否则不算完成。

## 每周标准动作（SOP）

| 时间 | 动作 | 产出 |
|---|---|---|
| 周一 上午 | 把上周周报发给导师 | `02_reports/` 里的最终版 |
| 周一 下午 | `new-target.ps1` 建本周文件夹，定题，填 `META.md` | `01_targets/2026-Wxx_平台-靶机/` |
| 周二–周四 | 打靶。**边打边记** `NOTES.md`，原始输出直接重定向进 `01_recon/` 等 | 过程数据 |
| 周五 | 复盘卡点。没打穿就看 writeup 的提示，然后回滚快照**裸打第二遍** | `NOTES.md` 补完 |
| 周六 | 写 `REPORT.md`（四段格式），把可复用的结论提炼进 `03_knowledge/` | 周报草稿 |
| 周日 | 定稿；`publish-report.ps1` 导出；需要时转 PDF | 交付物 |
| 周一 上午 | 发送 | ✅ 闭环 |

> 时间紧的周：宁可简单靶机 2 小时打完，也不要断更。**连续交付本身就是导师最看重的信号。**

## 授权与合规

本目录内所有操作仅针对**自己搭建的靶机、自己下载的固件、已获书面授权的设备**。
不触碰学校网络、实验室真实设备、任何公网目标。国内红线：《网络安全法》第 27 条，刑法 285/286 条。
`04_loot/` 中的 flag、hash、凭据一律不入 Git，不对外分享。

## 使用说明

1. 首次使用：确认 `00_meta/选题清单.md` 里的 8 周路线是否符合导师要求，按需调整。
2. 每周一只需要一条命令建目录，然后从 `META.md` 开始填。
3. 学期末把 `01_targets/` 整体移入 `05_archive/`，`03_knowledge/` 保留并整理成《IoT 漏洞挖掘入门笔记》。
