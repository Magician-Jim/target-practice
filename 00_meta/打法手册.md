# 打靶作战手册 v1.1

> 用途：单台靶机的执行规程。打之前扫一遍，打的时候当 checklist 用。
> 配套：产物落盘位置见第 6 节；周报写法见 [周报规范](./周报规范.md)。
>
> **v1.1 修订**：本机是 VMware Workstation **Player 17**，**不支持快照**（连 `vmrun` 命令行都返回"此操作不受支持"，已实测）。
> 原文所有"打快照/回滚快照"改为**「关机后复制虚拟机文件夹」**，见第 2 节。

---

## 1. 三条铁律

1. **只打自己搭的靶机、自己下载的固件。** 学校网络、实验室真实设备、公网目标一律不碰。
2. **开工前留一份干净副本，收工恢复。** Player 没有快照，用文件夹副本代替（第 2 节）。靶机被自己打崩、改坏是常态。
3. **边打边记。没有记录的一小时 = 没打。** 记录的是"命令 + 为什么敲 + 关键输出 + 当时判断"，不是命令流水账。

## 2. 干净副本：Player 版的做法

### 为什么不能用快照

| 版本 | 快照 | 说明 |
|---|---|---|
| Workstation **Pro** | ✅ | 图形界面 + `vmrun` 都支持 |
| Workstation **Player** | ❌ | 快照/克隆是 Pro 的功能，图形界面没有入口，`vmrun snapshot` 报"此操作不受支持" |

### 怎么做

**备份（开工前，1 分钟）**

```powershell
# 1. 先把靶机【关机】（不是挂起）
# 2. 复制整个虚拟机文件夹到备份目录
.\scripts\backup-vm.ps1 -Name phpblog
```

或者手工：把 `D:\Science\VM Workstation Player\` 下所有 `phpblog*` 文件（`.vmx` `.vmdk` `.vmsd` `.vmxf`）复制到
`04_lab\images\_backup\phpblog_clean\`。

**恢复（打崩了 / 想重打第二遍）**

```powershell
# 1. 靶机必须关机
# 2. 删掉当前的文件，把备份拷回来
Remove-Item 'D:\Science\VM Workstation Player\phpblog*' -Force
Copy-Item 'D:\Science\IoT\target-practice\04_lab\images\_backup\phpblog_clean\*' 'D:\Science\VM Workstation Player\'
```

### 三条注意

- **必须在关机状态复制**。开机复制会得到一个损坏的磁盘。
- 备份目录不要放进 git（`.gitignore` 已排除 `04_lab/images/*`）。
- 3 GB 左右的靶机复制约 1 分钟；比快照慢，但比"打崩了只能重新导入"快得多。

## 3. 单台 4 小时时间盒

| 时段 | 阶段 | 硬性产出 |
|---|---|---|
| T+0:00–0:15 | 环境就绪 | 备份已就位、计时开始、`NOTES.md` 建好 |
| T+0:15–0:45 | 信息收集 | 「端口—服务—版本—可疑点」表 |
| T+0:45–1:50 | 立足点 | 一个 shell（哪怕是 www-data） |
| T+1:50–2:50 | 提权 | root / 一条完整因果链 |
| T+2:50–3:20 | 收尾 | root flag、恢复副本、截图 |
| T+3:20–4:00 | 成稿 | 周报草稿（趁热，隔夜忘一半） |

时间盒的意义不是逼你 4 小时打完，是**让你在打不完的时候知道"该停了"**，把时间留给报告。

## 4. 五段式 checklist

### 4.1 信息收集（决定上限）

- [ ] 连通性：`ping` / `arp-scan -l` / `netdiscover`
- [ ] **全端口**：`nmap -p- --min-rate 2000 -T4 -oN nmap_all.txt <ip>`（别只扫 top1000，题眼常在高端口）
- [ ] 服务版本：`nmap -sC -sV -p<ports> <ip> -oN nmap_svc.txt`
- [ ] Web 指纹：`whatweb`、`curl -I`，看 Server / X-Powered-By
- [ ] 目录：`ffuf -w /usr/share/wordlists/dirb/common.txt -u http://<ip>/FUZZ`
- [ ] 顺手看：`robots.txt`、`.git/`、`backup.zip`、`index.php.bak`
- [ ] 虚拟主机：`ffuf -H "Host: FUZZ.<domain>"`
- [ ] 共享服务：`smbclient -L //<ip>/ -N`、ftp 匿名、redis/mongo 未授权
- [ ] 版本 → 漏洞：`searchsploit <服务> <版本>`，每个版本号都查

> 产出是一张表。表里"可疑点"那一列，是后面所有动作的来源。

### 4.2 立足点（拿第一个 shell）

按性价比从高到低试，**不要跳步**：

1. **默认/弱口令**：admin/admin、guest、空密码、靶机名当密码
2. **已知 CVE**：版本对上就直接打（searchsploit / GitHub PoC）
3. **Web 漏洞**：上传点 → webshell；参数点 → `;id`、`|id`、`$(id)`；LFI → `/etc/passwd`、日志投毒；SQLi → 拖库拿 hash
4. **未授权服务**：redis 写 cron、mongo 无认证、docker API

拿到 shell 的第一组命令背下来：

```bash
id; hostname; uname -a; cat /etc/os-release; ip a
```

升级 TTY（否则 sudo 会报错）：

```bash
python3 -c 'import pty;pty.spawn("/bin/bash")'
# Ctrl-Z → stty raw -echo; fg → export TERM=xterm
```

### 4.3 提权（Linux，按命中率排序）

- [ ] `sudo -l` —— **永远第一个看**
- [ ] `sudo -V` → CVE-2021-3156 之类
- [ ] SUID：`find / -perm -4000 -type f 2>/dev/null` → 丢进 GTFOBins 对照
- [ ] 定时任务：`crontab -l`、`cat /etc/crontab`、`ls -la /etc/cron.*`（看脚本是否可写）
- [ ] capability：`getcap -r / 2>/dev/null`
- [ ] 本机监听：`ss -tlnp`（只绑 127.0.0.1 的往往有洞）
- [ ] 文件里的凭据：`.bash_history`、`.ssh/`、`config.php`、`wp-config.php`、`.env`
- [ ] 可写服务文件 / 可写 PATH / NFS `no_root_squash`
- [ ] 内核版本 → 本地提权 exp（**最后手段**，容易崩机，崩了就恢复副本）

> 验收标准不是"我 root 了"，是"我能一句话说清：哪个配置、哪个版本、哪行代码，让 www-data 变成了 root"。

### 4.4 收尾

- [ ] 拿到 proof（`/root/root.txt` 之类）
- [ ] 截图关键界面（进 `05_evidence/`）
- [ ] 恢复干净副本（第 2 节）
- [ ] 30 分钟内整理成周报草稿

## 5. 卡住规则（防时间黑洞，最重要的一节）

| 情况 | 动作 |
|---|---|
| 某分支 30 分钟无进展 | 在 `NOTES.md` 写下"当前假设：___；否证方式：___"，换分支 |
| 累计 2.5 h 没 shell | 只看 writeup 的**提示/思路**部分，取一个方向，继续自己打 |
| 累计 3.5 h 没 root | 看完整 writeup，然后**关掉它，恢复副本裸打一遍** |
| 任何单点 | 不超过 45 分钟 |

裸打第二遍时"看懂了但打不出来"的地方，才是要写进周报的卡点。

## 6. 从靶机到 IoT 的翻译表（周报"根因"与"映射"两节的素材来源）

| 靶机里的东西 | 在 IoT 固件里长什么样 |
|---|---|
| Web 后台默认口令 | 摄像头/路由器出厂弱口令（Mirai 的燃料） |
| cgi-bin 命令注入 | IoT 最经典漏洞类别，`system()` 拼参数 |
| 老版本 busybox / httpd | 固件常年不更新，版本一查一大片 CVE |
| SUID 提权 | 嵌入式 Linux 权限配置错误、root 跑 web 服务 |
| 硬编码凭据 | `strings` 固件直接捞，或 `binwalk -e` 后搜 |
| 未授权服务 | 出厂调试端口（telnet 23、ADB、TR-069） |

打靶机练的是**攻击链构造**；漏洞挖掘要的是**单点根因定位**。两条腿都要，但周报要往后者倾斜。

## 7. 产物落盘位置（每做完一步，东西该在哪）

| 动作 | 产物 | 落到哪里 |
|---|---|---|
| 端口/目录扫描 | nmap、whatweb、ffuf 原始输出 | `01_recon/` |
| 查 CVE、试 PoC | exploit 脚本、payload、复现步骤 | `02_exploit/` |
| 提权枚举 | linpeas 输出、`sudo -l`、SUID 清单 | `03_privesc/` |
| 拿到 flag/凭据 | flag、hash、密码 | `04_loot/`（git 忽略） |
| 截图/录屏 | png、mp4 | `05_evidence/` |
| 打的过程 | 时间线、假设、卡点 | `NOTES.md` |
| 打完后的结论 | 四段式周报 | `REPORT.md` |
| 对外发布 | 完整 writeup | `WP.md` |
| 可复用结论 | 一句话能带走的经验 | `03_knowledge/<分类>/` |

## 8. 环境清单（一次配好，之后不用再想）

- VMware Workstation 17 Player（**无快照**，用 `scripts/backup-vm.ps1` 备份）
- 攻击机：Kali 或现成的 Ubuntu（装 `nmap arp-scan net-tools` 即可开局）
- 靶机来源：本地 OVA / THM 在线 / HTB 在线 / VulnHub 离线
- 笔记：VS Code 或 Obsidian，一台靶机一个文件夹
- 终端记录：`script -a session.log` 或 tmux `pipe-pane`
- IoT 侧：`binwalk`、`unsquashfs`、`firmadyne`/`FirmAE`、`qemu-user-static`、Ghidra
