# 知识沉淀区

> 这里的每一条，都必须是从某台靶机里**打出来**的，不是抄来的。
> 抄来的东西记不住，打出来的东西忘不掉。

## 什么该放进来

一台靶机打完，问自己一个问题：**下次遇到同类问题，我需要重新查资料吗？**

- 需要 → 写一张卡片放这里
- 不需要 → 什么都不用做

典型可沉淀内容：

| 分类 | 例子 |
|---|---|
| `web/` | 文件上传绕过的 5 种姿势、SQLi 报错注入的回显条件、SSRF 打内网的常见入口 |
| `linux/` | SUID 提权的 GTFOBins 常用项、cron 可写脚本的利用条件、capability 提权清单 |
| `iot/` | 固件拆包流程、squashfs 里找 web 服务的套路、命令注入点的静态识别特征 |
| `cve/` | 复现过的 CVE：版本范围、触发条件、PoC 路径、补丁 diff 关键行 |
| `cheatsheet/` | 自己高频敲但总记不住的命令 |

## 卡片怎么写

一个文件一个主题，文件名用中文概念名（半年后你搜的是概念，不是英文拼写）：

```markdown
# SUID 提权

## 一句话
SUID 位让普通用户以文件所有者权限执行，如果这个文件属于 root 且能被利用，就是提权点。

## 怎么找
find / -perm -4000 -type f 2>/dev/null

## 怎么判
丢进 GTFOBins 查，重点看有没有 shell 逃逸 / 文件读写 / 参数注入三类。

## 踩过的坑
- `find` 本身的 SUID 是经典项，但很多机器上被去掉了，先确认再花时间。
- 提权脚本（linpeas）会把 SUID 列出来，但不会告诉你哪个能用，判断还得自己做。

## 出处
THM / Basic Pentesting（2026-W45）
```

## 维护规则

- 一张卡片不超过一屏，超过就拆。
- 必须写"踩过的坑"，那是别处抄不到的。
- 必须写出处（哪台靶机、哪周），方便回溯上下文。
- 每 4 周把同类卡片合并一次，别让一个主题散成 8 个文件。
